# M3 Online Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** two friends on different devices and networks play a full game online. A join code or link connects them. Reconnection survives tab and app switches, reloads and a different device. The same referee runs on a self-hostable Node server and on Cloudflare Workers + Durable Objects.

**Architecture:**
- **`referee-core`** gains grace windows, claim-win, PIN rejoin with opponent approval, and deadline ticking. It still has no platform APIs.
- **`@wwd/referee-service`** holds the shared HTTP and connection policy: room creation, CORS, per-IP limits, frame caps and room retention.
- **Two thin adapters host it:**
  - `referee-node` (`ws` + `node:http`, JSON-file storage, Docker);
  - `referee-cloudflare` (one Durable Object per room, with the Hibernation WebSocket API, alarms, and SQLite-backed storage).
- **Browser side:**
  - a `WebSocketTransport`;
  - a `ConnectionManager` in `client-core` that owns reconnects, the mobile lifecycle and the watchdog;
  - the web app's online screens.
- **Deployment is configured but not run:**
  - GitHub Pages for the app;
  - `wrangler` for the Worker (staging and production);
  - a deployment guide for the account-side steps.

**Tech stack:**
- existing: Rust/WASM engine, TypeScript, Svelte 5, Vitest, Playwright;
- new: `ws` (Node), `wrangler`, `@cloudflare/vitest-pool-workers`, `@cloudflare/workers-types`.

**Spec:** `/docs/superpowers/specs/2026-11-22-werewolf-duel-online-design.md`

- **Platform rules:**

  - Cloudflare-specific code lives **only** in `referee-cloudflare`.
- **Never test against real Cloudflare.** Tests use in-memory referees, `referee-node` on localhost, and `@cloudflare/vitest-pool-workers` or `wrangler dev` (local workerd).
- **Protocol stays at version 1.** Nothing has been deployed yet, so additions are made in place.
- **Constants:**

  | Name | Value |
  |---|---|

  | `PIN_LENGTH` | 4 decimal digits |
  | `PIN_MAX_FAILURES` | 5 (after this, the seat's PIN is locked) |
  | `PIN_LOCK_MS` | 900 000 |
  | `REJOIN_APPROVAL_TIMEOUT_MS` | 120 000 |
  | `PING_INTERVAL_MS` | 30 000 while visible |
  | `PONG_TIMEOUT_MS` | 3 000 after resume |

  | `IDLE_ROOM_TTL_MS` | 30 days |
  | `FINISHED_ROOM_TTL_MS` | 24 h |

- **HTTP API:** identical on both adapters.
  - `POST /rooms` takes JSON `{ config: RulesConfig, grace_minutes: 5|10|30, test?: { grace_ms?: number, seed?: string } }`.
    - It returns `201 { code }`, or `400 {error}`, `429 {error}`, `503 {error}`.
    - `test` is honoured only when the server was started with test overrides enabled; otherwise it's `400`.
  - `GET /rooms/{CODE}/ws` is the WebSocket upgrade.
  - `GET /health` returns `200 { ok: true, protocol_version, engine_version }`.
  - **CORS:** origins come from config `allowed_origins` (comma-separated), with `http://localhost:*` allowed when test overrides are enabled.
- **Client conventions:**
  - The referee URL comes from Vite env `VITE_REFEREE_URL`, overridable per game by an invite link's `server=` parameter.
  - Invite link: `<app origin>/#/join/<CODE>`, plus `?server=<url-encoded>` only when it differs from the default.
- **Conventions (CLAUDE.md):** British English, sentence-case Fluent strings, conservative self-contained comments, and the unofficial notice on every screen.

## Review Focus

1. **A hello carrying a token that matches no seat** gets `error{code:'unknown_seat', close:true}` and never claims a seat. This replaces "claims a fresh seat".
   - The client then offers "Join as a new player" (a `hello` without a token) only if the room isn't full.
   - Test: `unknown token never claims a seat` (Task 3).
2. **PIN brute force:**
   - The 6th wrong PIN within the lock window gets `pin_locked`, even with the right PIN.
   - The opponent receives `opponent_status` with `pin_attempt_failed: true`.
   - The lock survives `snapshot`/`restore`.
   - Test: `pin lockout survives restore` (Task 4).
3. **Claim-win timing:**
   - `claim_win` before the opponent's grace deadline gets `not_expired`.
   - After it, the referee applies `Resign` for the absent seat.
   - Both seats get `game_over`, and the replay verifies.
   - A reconnect after the claim gets `game_over`.
   - Test: `claim win only after grace` (Task 3).
4. **Hibernation:**
   - A Durable Object woken by `webSocketMessage` after eviction rebuilds the room from storage, rebinds every attached socket from its serialised `{conn, seat}`, and closes any socket without an attachment.
   - Play then continues with no `not_joined`.
   - Test: `room survives eviction` (Task 7).
5. **Mobile lifecycle:**
   - When the page is hidden, the socket closes and no pings are sent.
   - On becoming visible, it reconnects with `last_seq`, with no duplicate events.
   - After a timer gap over 10 s, it reconnects.
   - A `pageshow` with `persisted: true` reconnects.
   - Test: `lifecycle reconnects without duplicates` (Task 8).

### Task 3: `referee-core` grace windows, claim-win, resign, unknown-token policy

**Files:**

**Interfaces (Produces):**
```ts
export interface RoomOptions { graceMs: number }                 // default 600_000
Room.create(code, config, deps, options?: Partial<RoomOptions>): Room
Room.restore(snapshot, deps): Room                                // accepts RoomSnapshot v1 (migrated) and v2
room.tick(): Outbound[]                                           // processes every deadline <= clock.now()
room.nextDeadline(): number | null                                // earliest pending deadline (grace, approval timeout, pin unlock)
room.lastActivityAt: number                                       // getter; any handled message or tick that changed state
room.finishedAt: number | null                                    // getter; when game_over was first reached
interface RoomSnapshot { version: 2; …v1 fields…; grace_ms: number; disconnected_at: [number|null, number|null];
  pins: [string|null, string|null]; pin_failures: [number[], number[]]; pin_locked_until: [number|null, number|null];
  last_activity_at: number; finished_at: number | null }
```
- **Grace windows:**
  - When a seated connection disconnects mid-game (game started, not over), record `disconnected_at[seat] = now`.
  - The opponent gets `opponent_status{connected:false, grace_deadline: now + graceMs}`.
  - When `tick()` finds the deadline passed, the opponent gets `opponent_status{connected:false, can_claim_win:true}`.
  - A reconnect clears the disconnect and sends `opponent_status{connected:true}`.
- **Claim win:**
  - `claim_win` from a seat whose opponent is disconnected past the deadline → `game.apply(opponentSeat, Resign)`, then the usual `events` + `game_over` to the bound seats.
  - Otherwise `not_expired`. After game over, it's `error-game-over`.
- **Resign:** `command{cmd:'resign'}` from a bound seat is applied through the engine (it's not in `legal`, but the engine accepts it).
- **Unknown token:** a `hello` whose `seat_token` matches neither seat replies `error{unknown_seat}` with `close:true` (Review Focus 1).
- **Snapshots:** v2 adds the fields above. v1 snapshots migrate with defaults (`grace_ms` 600 000, no pins yet: Task 4 generates them on the next welcome).

### Task 4: `referee-core` PIN rejoin with opponent approval

**Files:**
- Modify: `app/packages/referee-core/src/room.ts`, `snapshot.ts`
- Test: `app/packages/referee-core/test/rejoin.test.ts`

**Interfaces (Produces):**
- `welcome.pin`: generated at seat claim from `Random`, as 4 uniformly distributed digits (rejection-sampled). It's stored in the snapshot and repeated in every `welcome` for that seat.
- **`rejoin{room, seat, pin}`:**
  - **Right PIN, not locked:** the seat gets a **new** seat token. Any connection previously bound to that seat gets `superseded` with `close:true`. The rejoiner gets `welcome` (new token, same PIN), then `events` from 0. The opponent gets `opponent_status{connected:true}`.
  - **Wrong PIN:** record a failure timestamp and reply `wrong_pin`. The opponent gets `opponent_status{…, pin_attempt_failed:true}`. More than `PIN_MAX_FAILURES` failures within `PIN_LOCK_MS` sets `pin_locked_until`, and every attempt then gets `pin_locked` (Review Focus 2).
  - **Pin omitted:**
    - If the opponent is connected: the rejoiner gets `rejoin_pending` and the opponent gets `rejoin_request`, with an approval deadline (`REJOIN_APPROVAL_TIMEOUT_MS`).
    - `approve_rejoin{approve:true}` from the opponent grants the seat, as for a right PIN. `false`, or the timeout, sends the rejoiner `rejoin_declined` with `close:true`.
    - If the opponent isn't connected: `rejoin_unavailable`.
    - Only one pending request per room; a second one gets `rejoin_unavailable`.
- **Pre-game:** rejoin applies to claimed seats before the game starts too.

### Task 6: `referee-node` adapter

**Files:**
- Create: `app/packages/referee-node/{package.json,tsconfig.json,Dockerfile,.dockerignore,README.md}`
- Create: `app/packages/referee-node/src/{index.ts,server.ts,file-store.ts,connection.ts,cli.ts}`
- Test: `app/packages/referee-node/test/{server.test.ts,lifecycle.test.ts}`, using real `ws` clients against an ephemeral port.

**Interfaces (Produces):**
```ts
export interface NodeRefereeOptions { port: number; host?: string; dataDir?: string; allowedOrigins: string[]; testOverrides?: boolean; trustProxy?: boolean; clock?: Clock; random?: Random }
export async function startReferee(opts: NodeRefereeOptions): Promise<{ url: string; close(): Promise<void> }>;
// bin "wwd-referee": --port 8787 --host 0.0.0.0 --data ./data --origins <list> [--test-overrides] [--trust-proxy]
```
- **HTTP:** `node:http` server. Requests are bridged to `handleHttp` as WHATWG `Request`s. Upgrades use `ws` (`WebSocketServer({ noServer: true, maxPayload: MAX_FRAME_BYTES })`).
- **Rooms:**
  - Rooms live in memory, one `Room` per code.
  - After every `handle`/`tick`/`disconnect` that changed state, the snapshot is written to `<dataDir>/<CODE>.json` with an atomic write (temp file + rename), unless the room is `faulted`.
  - On startup, rooms are loaded lazily from disk, and connections are re-established by clients (no rebind needed for Node).
- **Connections:** each socket gets a `ConnId`.
  - It's closed if no valid `hello`/`rejoin` arrives within `PRE_HELLO_TIMEOUT_MS`.
  - At most `MAX_CONNECTIONS_PER_ROOM` per room.
  - Every outbound message is sent, then the socket is closed when `close` is set (code 1000).
  - A handler exception on one connection logs and closes only that socket.
- **Timers:** one `setTimeout` per room, scheduled at `room.nextDeadline()`, which calls `tick()`. Plus an hourly sweep that deletes expired rooms (`isExpired`) and their files.
- **Faults:** a `faulted` room gets all its sockets closed with 1011, it's dropped from memory, and the process logs it. It isn't persisted.
- **Client IP:** `X-Forwarded-For` (first hop) only with `trustProxy`; otherwise the socket address.
- **Dockerfile:**
  - multi-stage: a builder with Rust + wasm target + `wasm-bindgen-cli` + pnpm that builds the workspace;
  - a runtime of `node:24-slim` running `node dist/cli.js`, as a non-root user, with `/data` as a volume;
  - `docker build` isn't required in tests. If Docker is available locally, build once and note it in the report.
