# M4 Product Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** turn the bare online table into the finished app: every mocked screen in the Moonlit theme, settings, pause and resume (including from a save file), rematch, history with replays and stats, backups, and an installable PWA that opens offline.

**Architecture:**
- **Engine:** a few pure helpers for the UI (plan validation with a reason, effective initiative, showdown order from a view, a replay timeline) and resuming a game in a new segment. The UI still decides no rules: every rule-shaped question goes to the engine.
- **Protocol v2 and `referee-core`:** pause after the current round, resume when both players are ready, rematch in the same room, and a room created from a verified save file. Snapshot v3 records the new state. Both adapters pass the new messages through unchanged.
- **Browser side:**
  - `client-core` gains the pause, resume and rematch state, and the "server unavailable" signal.
  - `apps/web` gains a device store in IndexedDB, a settings model applied to the document, the design system, and the screens.
  - A service worker gives an offline shell and an update prompt.

**Tech stack:**
- existing: Rust/WASM engine, TypeScript, Svelte 5, Vite, Vitest, Playwright, `ws`, wrangler;
- new: `idb` (IndexedDB), `vite-plugin-pwa` (manifest and Workbox service worker), a small dependency-free QR SVG generator (for example `uqr`), `@fontsource/*` packages for the OFL fonts, and `@axe-core/playwright`.

**Spec:** `/docs/superpowers/specs/2026-11-22-werewolf-duel-online-design.md`
- §6.2 engine API and replay format;
- §6.4 protocol, §6.5 referee (pause, save files, "Notes for M4"), §6.6 client;
- §7 data on the device, install, backup, history;
- §8 UX: screens, settings, visual language, fonts, accessibility;
- §9 budgets, §10 testing.

**Scope**
- **In:** everything above, plus the M4 notes from the M3 final review (Node idle unload, PIN attempts bounded over a room's lifetime, the Docker image built in CI, server-unavailable messages) and the Home "Continue" list deferred from M3.
- **Not in M4:**
  - DE and JA, their fonts, the pseudo-locale CI check, the full accessibility audit, the rewritten rulebook and the tutorial (M5). Home's "How to play" opens the character reference only.
  - Gameplay settings that need rules reasoning the engine doesn't expose yet: "Warn on pointless targets", "Hunter: auto when a target matches" and "Tutorial tips" (M5).
  - "Data saver": there are no avatars or prefetching to turn off (later).
  - Scanning a QR inside the app. The QR encodes the invite link, so a phone's own camera opens it.
  - Third-party icon packs. Markers and characters use our own SVG shapes in M4; credits are added if a pack is adopted later.

## Decisions (record in the spec in Task 15)

| Topic | Decision |
|---|---|
| Protocol version | `PROTOCOL_VERSION` becomes **2**. The app is deployed, so an old cached page gets `protocol_version` and the existing "reload" message. |
| When a pause applies | At the **first round boundary** after both seats agree (`Phase::RoundOver` with neither seat ready). Agreed during a round, it waits for the round's end; agreed in `RoundOver` after one seat already chose "Next round", it applies at the next round's end. |
| Resume | A paused room resumes only when both seats are connected **and** both have sent `resume_request`. Connecting alone never resumes. |
| Resume from a save file | Friend mode: **one verified upload** (spec §11). `POST /rooms` with the save and the uploader's seat. The referee verifies the replay, refuses a tainted one, and checks that the boundary is where the replay ends. |
| Rematch | Same room. Both seats send `rematch_request`; the new game has a fresh seed and `badge_start: Seat(loser)`. Each game in a room has an index, and sequence numbers restart at 0 for each game. |
| PIN lockout over a room's life | Each lockout doubles the lock: 15 min, 30 min, 1 h … capped at 24 h. The count resets on a successful PIN rejoin. About 230 attempts fit in 30 days, not 17 000. |
| Node memory | A room with no connections is written and dropped from memory after `IDLE_UNLOAD_MS` (10 min); it reloads lazily. |
| Docker | Built and smoke-tested in CI (a new `docker` job), since there is no Docker on the development machine. |
| Storage | IndexedDB via `idb`. M3's `localStorage` sessions are migrated once, then removed. |
| Icons | Our own SVGs for characters (shape + pattern + glyph + number) and markers. |
| Fonts | Self-hosted `@fontsource` packages, Latin subsets only. Body and headings load at start; Lexend and OpenDyslexic load only when chosen. If OpenDyslexic has no package on npm from a trusted publisher, it is left for M5 and the option is hidden. |

## Review Focus

1. **A save file that has been tampered with or comes from another game.** `POST /rooms` with an edited, tainted or truncated save, or one whose boundary doesn't match where its replay ends, gets `400 {error: "invalid_save"}` and creates nothing. Test: `room from save rejects tampered saves` (Task 3).
2. **Pause agreed in the middle of a round.** The current round finishes normally, and no deal happens before the pause applies; a seat that already chose "Next round" doesn't cause a deal while the pause is pending. Test: `pause waits for the round boundary` (Task 2).
3. **Hidden information in saves, history and backups.** A save holds no live seed and no seat-private data from an unfinished segment; history keeps the full log only once a game is over; a backup contains seat tokens, so its export warns that it belongs to this device's player only. Tests: `save holds no live secrets` (Task 2), `backup export warns about seat tokens` (Task 13).
4. **An old cached page after a deploy.** A page running protocol 1 against the new referee shows "This page is out of date", and the update banner offers a reload that activates the new service worker. Test: `stale page is told to reload` (Task 14).
5. **A browser without IndexedDB or with storage blocked** (some private windows). The app still plays an online game, keeps settings for the tab only, and says that history and saves won't be kept. Test: `app works without IndexedDB` (Task 5).

### Task 2: Protocol v2, pause and resume in `referee-core`

**Files:**
- Modify: `app/packages/protocol/src/{messages.ts,codes.ts}`, `app/packages/referee-core/src/{room.ts,snapshot.ts}`
- Create: `app/packages/referee-core/src/pause.ts` (pure pause bookkeeping, as `pin-lockout.ts` is for PINs)
- Test: `app/packages/protocol/test/*`, `app/packages/referee-core/test/pause.test.ts`

**Interfaces (Produces):**
```ts
// client → referee
{ type: 'pause_request' } | { type: 'pause_cancel' } | { type: 'pause_accept' } | { type: 'resume_request' }
// referee → client
{ type: 'pause_status', requested_by: Seat | null, agreed: boolean }
{ type: 'paused', save: SaveFile }
{ type: 'resume_status', ready: Seat[] }
// new error codes: 'paused' (a command while paused), 'not_pausable'
interface SaveFile { format_version: 1; kind: 'wwd-save'; room: string; config: RulesConfig;
                     boundary: RoundBoundary; replay: Replay; saved_at: number; hash: string }
```
- `pause_request` from either seat while a game is in progress and not paused; the other seat's `pause_accept` agrees; either seat's `pause_cancel` withdraws a request or agreement. `pause_status` goes to both seats on every change and on every `welcome`.
- **Applying:** when agreed and the engine has a round boundary (`Game.roundBoundary()` not null), the room becomes paused: it sends `paused{save}` to both seats, stops grace windows, and rejects commands and `claim_win` with `error{paused}`.
- **The save** holds the boundary, the config and the replay so far. Its last segment is closed: its seed is included because all of its deals are finished. `hash` is `contentHash` (Task 1) of the canonical JSON of the other fields: keys sorted, no whitespace.
- **Resuming:** once both seats are bound and both have sent `resume_request`, the room calls `Game.resume(boundary, replay, newSeed)` with a seed from `random`, and both seats get `events` starting with `SegmentStarted`. `resume_status` goes to both seats on every change.
- **Snapshot v3** adds `pause: {requested_by, agreed, paused: boolean, resume_ready: Seat[]}`. v1 and v2 upgrade with no pause.
- **Retention:** a paused room is idle until resumed (`IDLE_ROOM_TTL_MS`).

- [ ] **Step 1: Write failing tests**

  - `pause applies at once in round over`; `either seat can cancel`; `cancel after agreement withdraws it`.

  - `save holds no live secrets` (Review Focus 3): the save's replay verifies; its last segment's seed is the one just finished; nothing in it equals the room's next seed; no seat-private event of an unfinished segment appears.
  - `resume needs both seats ready`; `resume deals with a new seed` (the new commitment differs, and the final replay verifies across segments).
  - `pause survives restore` for both plain and `{wake: true}` restores; `v2 snapshot upgrades to v3`.
  - protocol: every new message parses, and a v1 `hello` gets `protocol_version`.

### Task 3: Rematch, and a room created from a save file

**Files:**
- Modify: `app/packages/protocol/src/{messages.ts,http.ts,codes.ts}`, `app/packages/referee-core/src/room.ts`, `app/packages/referee-service/src/{service.ts,adapter.ts}`

**Interfaces (Produces):**
```ts
{ type: 'rematch_request' }                          // client → referee, after game over
{ type: 'rematch_status', ready: Seat[] }            // referee → client
// welcome and events gain: game: number             // 0 for the room's first game
// hello gains: seat?: Seat                          // honoured only for an unclaimed seat of a room created from a save
// POST /rooms body: { config, grace_minutes, test? } | { save: SaveFile, seat: Seat, grace_minutes }
// 400 { error: 'invalid_save' }
Room.fromSave(code, save, seat, deps, opts): Room    // verified; starts paused, both seats unclaimed, `seat` reserved for the first hello that names it
```
- **Rematch:** after `game_over`, once both seats send `rematch_request`, the room starts game `n + 1` with a fresh seed and `badge_start: {seat: loser}`, keeps both seat tokens and PINs, clears `finished_at`, and sends `events` with `game: n + 1` starting at `seq` 0. The finished game's replay stays available to a reconnecting seat only until the rematch starts.
- **From a save:** the referee checks `format_version`, `hash`, `verifyReplay`, `!replay.tainted`, and that the replay's final state has exactly `boundary` as its round boundary. Then the room is paused with seats unclaimed. The first `hello` without a token that names `seat` claims it; the next claims the other. Resuming then works as in Task 2.
- The rate limit, body cap (`MAX_MESSAGE_BYTES` still applies to WebSocket messages; the HTTP body cap for a save is `MAX_SAVE_BYTES` 262 144) and origin rules apply to `POST /rooms` as before.

  - `room from save rejects tampered saves` (Review Focus 1): edited hash, edited command, tainted replay, mismatched boundary, wrong `format_version`, oversized body (`413`).
