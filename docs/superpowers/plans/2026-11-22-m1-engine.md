# M1 Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone, deterministic Rust rules engine for Werewolf: Duel!, with per-player views, legal-move enumeration, replays, unsafe test edits, and a `wwd` CLI.

**Architecture:**
- A pure state machine (`State` + `apply(seat, Command) -> Vec<Event>`) in the `wwd-core` crate.
- Automatic steps (dealing, revealing, resolving, round end) run inside `apply` until the next player input is needed.
- Players only ever see data through `view()` and visibility-filtered events.
- `wwd-cli` is a thin binary over the public API.

**Tech Stack:**
- Rust stable (1.98 installed)
- serde + serde_json
- postcard (canonical bytes for hashing)
- blake3
- rand_chacha / rand_core (ChaCha8)
- clap
- fluent-bundle
- proptest

**Spec:** `/docs/superpowers/specs/2026-11-22-werewolf-duel-online-design.md`. §5 is the authoritative rules, and §6.2–6.3 the API and CLI.

**Scope:**
- This plan is milestone M1 only.
- Separate plans follow for M2 (WASM bindings, protocol crate, referee core, client core, unstyled web table), M3 (online), M4 (product screens), and M5 (i18n, accessibility, rulebook).
- The `wasm` and `protocol` crates are **not** created here.

## Global Constraints

- **Repo:** single repository (this one). The engine lives in `engine/`: a self-contained Cargo workspace with `crates/wwd-core` (lib) and `crates/wwd-cli` (bin `wwd`), licensed MIT OR Apache-2.0. **All task paths below are relative to `engine/`, and all commands run from `engine/`**, unless they start with `/` for the repo root.
- **Git:** the user manages the repository. If it doesn't exist yet, or the user hasn't asked for commits, skip each "Commit" step: leave the changes uncommitted and report the suggested commit message instead.
- **Determinism:**
  - No `HashMap`/`HashSet` in `wwd-core`; use `BTreeMap`/`BTreeSet`/`Vec`.
  - No floats.
  - No clock, environment, locale, or `rand::thread_rng`.
  - All randomness comes from the state's ChaCha8 stream.
- **RNG state:** stored as `RngState { seed: [u8; 32], word_pos: u128 }`. It is reconstructed with `ChaCha8Rng::from_seed(seed)` + `set_word_pos`, never by serialising the RNG object.
- **Shuffling:** uses our own Fisher–Yates with rejection-sampled bounds over `next_u32`, not `rand::seq`, so results don't change when crate versions change.
- **Hashing:** `hash(&State) = blake3(postcard::to_stdvec(&State))`. `State` contains `engine_version: String` (the crate version).
- **Strings:** the engine emits IDs only. All human text lives in `locales/en/engine.ftl` (Fluent). Message IDs: `character-<kebab>`, `faction-<kebab>`, `event-<kebab>`, `error-<kebab>`.
- **Unsafe edits:** behind the cargo feature `unsafe-edit` only. Any edit sets `State.tainted = true`.
- **Run all tests with:** `cargo test --workspace --all-features`.
- **Constants:**

  | Constant | Value |
  |---|---|
  | `TOTAL_CROSS` | 7 |
  | `TOTAL_FANG` | 5 |
  | `TOTAL_HOURGLASS` | 5 |
  | `START_HEALTH` | 2 |
  | `WIN_CROSS` | 4 |
  | `WIN_FANG` | 3 |
  | Hand size, Badge holder | 4 |
  | Hand size, other player | 3 |

- **Default `RulesConfig`:** `{ tiebreak: HourglassesThenBadge, min_targets: 1, badge_start: Random }`.

## Review Focus

1. **Hourglass gain with an empty supply:**
   - The gain comes from the opponent's *unplaced* reserve, never from Hourglasses on their card.
   - If that reserve is empty, nothing happens and nothing goes negative.
   - Owner: Task 6, test `hourglass_gain_takes_from_opponent_reserve_only`.
2. **Effective initiative clamps at 0**, and the tie-break still applies. For example, Hunter (1) with 3 Hourglasses against Wolf King (2) with 2 Hourglasses: both are 0, so the player who placed 3 goes first.
   - Owner: Task 5, test `initiative_clamps_and_tiebreaks_on_hourglasses`.
3. **Elimination is once only, including after the Potion.** A character hit by the Potion does not act, and a later attack on it changes nothing (no extra Health loss).
   - Owner: Task 6, test `potion_eliminated_character_cannot_be_hit_again`.
4. **The game ends mid-Showdown.**
   - When a win or loss is reached (e.g. Villager's 4th Cross, Seer taking the last Health, with Health never below 0), later characters do not resolve.
   - Every further command returns `RuleError::GameOver`.
   - Owner: Task 7, tests `win_mid_showdown_stops_resolution` and `seer_damage_clamps_at_zero`.
5. **Wolf King edge cases:**
   - With only the Fool as a target: no payment and no attack.
   - With more extra targets than Fangs held: pays nothing and the whole attack fails, even if a target would have matched.
   - Owner: Task 6, test `wolf_king_payment_edges`.

pub struct RngState { pub seed: [u8; 32], pub word_pos: u128 }   // Serialize, Deserialize
impl RngState {
    pub fn new(seed: [u8; 32]) -> Self;
    pub fn next_u32(&mut self) -> u32;          // rebuild ChaCha8Rng, set_word_pos, draw, store new word_pos
    pub fn below(&mut self, n: u32) -> u32;     // uniform in [0, n): rejection on zone = u32::MAX - (u32::MAX % n)

pub fn hash_bytes<T: Serialize>(value: &T) -> [u8; 32]; // blake3(postcard::to_stdvec(value))

**Flow** (spec §5.3):
1. **SubmitPlan:**

### Task 6: Showdown resolution

**Files:**

**Interfaces (Produces):**
```rust
pub(crate) fn resolve_showdown(state: &mut State, events: &mut Vec<Event>); // runs until HunterChoice, GameOver, or round end
// new EventKind variants (all Public):
PotionResolved { target: Character, hit: bool },
CharacterResolved { seat, character },
MarkerGained { seat, marker: Marker, from_opponent: bool },   // Marker { Cross, Fang, Hourglass, Potion }
MarkerSpent { seat, marker: Marker, n: u8 },
AttackHit { seat, target_seat, character: Character, health_lost: u8 },
AttackMissed { seat },
AttackForfeited { seat, reason: ForfeitReason },              // ForfeitReason { NoCross, Declined, CannotPayFangs, NoTargets }
```

**Algorithm** (spec §5.3 Showdown; this ordering is fixed):
1. **Potion:**
   - If `potion_target = Some((holder, c))` and the opponent's plan character is `c`: mark the opponent eliminated and deal 1 damage.
   - Emit `PotionResolved`. Clear `potion_target`.
2. **For each seat `s` in `order`** (starting at `showdown.next`), skip it if eliminated. Otherwise:
   1. Mark `resolved[s] = true` and emit `CharacterResolved`.
   2. Apply the per-character rules:

      | Character | Rule |
      |---|---|
      | Hunter | If `cross == 0`, `AttackForfeited{NoCross}`. Otherwise set `phase = HunterChoice{s}` and **return**. `HunterSpendCross{true}` spends 1 Cross (to supply), then attacks. `{false}` gives `Forfeited{Declined}`. Resume at the next seat |
      | WolfKing | `extra = non_fool_targets.saturating_sub(1)`. If `non_fool_targets == 0`, `Forfeited{NoTargets}`. If `extra > fang`, `Forfeited{CannotPayFangs}` and pay nothing. Otherwise spend `extra` Fangs, then attack |
      | Knight, Wolfen | Gain an Hourglass, then attack |
      | Seer | Attack with damage 2 |
      | Witch | `potion = true`, `supply.potion = false`, `MarkerGained{Potion}` |
      | WolfBeauty | Gain a Fang, then attack |
      | Villager | Gain a Cross |

   3. **Attack:**
      - Let `o = s.other()`.
      - It hits if `plan[o].character ∈ targets`, `!resolved[o]` and `!eliminated[o]`.
      - On a hit: `eliminated[o] = true`, `health[o] = health[o].saturating_sub(dmg)`, emit `AttackHit` with the actual Health lost.
      - Otherwise emit `AttackMissed`.
   4. **Gain Hourglass:**
      - From the supply if > 0.
      - Otherwise from the opponent's `hourglass` reserve if > 0 (`from_opponent: true`).
      - Otherwise nothing.
      - Never take from `placed`.
   5. **Gain Fang or Cross:** from the supply (it can't be empty before a win).

**Game end** (spec §5.4). Check in this order, and stop at the first true:
1. Any player with health 0 → the other player wins (`Health`).
2. A player with fang ≥ 3 → they win (`Fangs`).
3. A player with cross ≥ 4 → they win (`Crosses`).

Because this runs after each single change, only one result is ever possible.

**Round end:**
1. Return all `placed` Hourglasses to the supply.
2. Clear plans, `showdown` and `discard`.
3. Pass the Badge, increment the round, and emit `RoundEnded`.
4. Call `start_round`.

**`view` redaction:**
- An opponent's `hand` is `None` (with `hand_size` set). For a Spectator, both hands are `None`; for Omniscient, both are `Some`.
- `plan`:
  - `Hidden{count}` from submission until `PlansRevealed`.
  - `Revealed` after reveal, until round end.
  - The viewer's own plan is always `Revealed` to them.
- The `discard` never appears in a `View`, except to Omniscient (add a field `discard: Option<Character>` that is `None` otherwise).
- `log` is filtered by `visible_to`.

**`legal_actions`:**
- In Plan: every `(character in hand) × (every non-empty subset of allowed targets ∪ {Fool} passing validate_plan)`.
- In the other phases: the valid `PlaceHourglasses{0..=reserve}`, `ChoosePotionTarget{c}` for unplayed characters, and `HunterSpendCross{true|false}`.
- An empty `Vec` when it isn't this seat's turn, or the game is over.
